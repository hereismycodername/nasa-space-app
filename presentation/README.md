# Питч AstroCheck: 8 слайдов на 3 минуты

Анимированная презентация в стиле самого приложения: приборная панель, прямые углы, срезы на панелях,
квадратные индикаторы, моноширинные подписи. Работает без интернета: шрифты, скриншоты и анатомия лежат рядом.

## Как показать

Откройте `index.html` в Chrome или Edge и нажмите `F` (полный экран). Сцена 1920×1080 сама подстраивается
под окно. Если браузер не открывает файл напрямую, поднимите локальный сервер из корня репозитория:

```bash
python -m http.server 8765 --bind 127.0.0.1 --directory presentation
```

и откройте `http://127.0.0.1:8765/`. Номер слайда хранится в адресе (`#3`), перезагрузка возвращает на него.

## Управление

| Клавиша | Действие |
|---|---|
| `→` `Space` `PageDown` `Enter` | следующий слайд |
| `←` `PageUp` `Backspace` | предыдущий слайд |
| `1`…`8`, `Home`, `End` | перейти к слайду |
| `N` | заметки докладчика (текст питча для слайда) |
| `T` | показать таймер питча и план по времени |
| `P` / `R` | пауза / сброс таймера |
| `A` | автопоказ: слайды сменяются сами за 3 минуты (удобно для записи видео) |
| `0` | повторить анимацию текущего слайда |
| `M` | выключить / включить анимацию |
| `F` | полный экран |
| `?` | подсказка по клавишам |

Клик мышью: правая часть экрана листает вперёд, левая пятая — назад. Кликер-презентер работает как стрелки.
Таймер запускается сам при первом переходе; на экране его нет, пока не нажата `T`.

## План и текст питча

| № | Слайд | Время | До | Что происходит на экране |
|---|---|---|---|---|
| 1 | AstroCheck | 15 с | 0:15 | Прибор «загружается»: строки самотестирования, фигура печатается сканирующей линией |
| 2 | Проблема | 25 с | 0:40 | Вопрос экипажа летит к Земле и обратно, счётчик доходит до 40 минут; пять опасностей |
| 3 | Решение | 25 с | 1:05 | Камера проходит четыре шага по реальному экрану веб-клиента |
| 4 | Карта тела | 25 с | 1:30 | Курсор переключает слои, кликает по голове, вносит симптом |
| 5 | Оценка | 25 с | 1:55 | Три коротких ночи — срабатывает правило, появляется следующий шаг |
| 6 | Данные | 20 с | 2:15 | Перо рисует неделю пульса и останавливается на пропуске; свежесть показателей |
| 7 | Архитектура | 25 с | 2:40 | Пакеты идут от источников через один сервер к трём интерфейсам |
| 8 | Итог | 20 с | 3:00 | Четыре слова и главное обещание, что работает и что дальше |

Анимация каждого слайда укладывается в первые 5–15 секунд, дальше остаётся спокойное движение
(сердцебиение, пакеты, мигающие индикаторы). Листать нужно один раз на слайд.

1. **AstroCheck.** Мы — команда AstroCheck. Наш инструмент помогает астронавту самому оценить своё здоровье
   в полёте и понять, что делать дальше, — даже когда Земля не на связи.
2. **Проблема.** На МКС врач доступен почти в реальном времени. По пути к Марсу сигнал идёт до двадцати минут
   в одну сторону — ответ придёт через сорок, а бывают и полные разрывы связи. NASA выделяет пять опасностей
   полёта: радиация, изоляция, удалённость от Земли, гравитация и замкнутая среда. Экипаж должен уметь
   оценивать себя сам.
3. **Решение.** AstroCheck — бортовой самоконтроль. Четыре шага. Наблюдение: двенадцать показателей с датчиков
   и ручного ввода. Объяснение: почему это важно именно в полёте. Действие: что сделать сейчас. Эскалация:
   когда звать экипаж и полётного врача. Всё хранится локально — ни интернет, ни связь с Землёй не нужны.
4. **Карта тела.** Главный элемент интерфейса — тело. Это реальная анатомия из открытого набора BodyParts3D:
   органы, скелет, рентген. Статус системы виден по тонкому контуру. Кликаешь по голове — открываются
   связанные показатели: сон, самочувствие, головная боль. Симптом вносится одним кликом и сразу попадает
   в историю.
5. **Оценка.** Система не ставит диагноз — она объясняет. Три дня сон меньше семи часов: срабатывает правило,
   статус меняется на «требует внимания». Астронавт видит причину, следующий шаг и момент, когда нужно
   подключать врача. У каждого правила — ссылка на источник: NASA, AHA, NHS, CDC. При критическом значении —
   отдельный красный сигнал.
6. **Данные.** Мы честны с данными. На графике пропуски остаются пропусками — мы их не дорисовываем. Каждое
   значение помечено свежестью: если замеру больше суток, система так и скажет и не станет оценивать по нему
   состояние. Повторная отправка с датчика не создаёт дублей.
7. **Архитектура.** Архитектура простая. Датчики, ручной ввод и симулятор пишут в один локальный сервер на Rust
   с базой SQLite. К нему подключаются три интерфейса: веб с 3D-моделью, оконное приложение и лёгкий терминал.
   Тот же сервер даёт вид для экипажа и консоль для полётного врача на Земле. Всё покрыто более чем двумястами
   автотестов.
8. **Итог.** Наблюдение, объяснение, действие, эскалация — без интернета. Это работает уже сейчас, на
   синтетических данных. Следующие шаги — реальные датчики через готовый шлюз и проверка на бортовом
   компьютере. Спасибо! Готовы показать живое демо и ответить на вопросы.

Не обещать на питче: диагнозы, медицинскую точность, работу на Raspberry Pi и с физическими датчиками
(см. `docs/demo-runbook.md`). Оговорка «не медицинское изделие, данные синтетические» стоит на последнем слайде.

## Что стоит перепроверить перед показом

- «NASA Space Apps 2026», ссылка на репозиторий и «200+ автотестов» взяты из корневого `README.md`.
- «До 20 минут в одну сторону» — формулировка NASA Human Research Program про удалённость от Земли; в
  репозитории этой цифры нет, сверьте с источником.
- Названия команды на слайдах нет — добавьте в `index.html`, если нужно.

## Как устроено

| Файл | Что в нём |
|---|---|
| `index.html` | Восемь слайдов (`<section class="slide">`), тексты, заметки докладчика в `<aside class="notes">` |
| `deck.css` | Готовый вид каждого слайда в палитре приложения (`ui/crates/ui-gui/src/theme.rs`) |
| `deck.js` | Масштаб сцены, навигация, таймер, заметки; собирает фигуру, график пульса и кадр терминала |
| `motion.css`, `motion.js` | Слой анимации: по сцене на слайд, переходы между слайдами |
| `assets/anatomy/` | Спрайты тела, скелета и органов, контуры систем, `manifest.js` с координатами |
| `assets/screens/` | Скриншоты веб-клиента (`web-*.webp`) и оконного приложения (`*.png`) |
| `assets/fonts/` | Inter и DM Mono с текстами лицензий OFL |
| `tools/export_anatomy.py` | Раскрашивает атлас анатомии в готовые спрайты для презентации |

`deck.css` описывает конечное состояние; `motion.js` анимирует *из* стартового состояния и отпускает элемент,
поэтому без скриптов (или с `?static` в адресе) презентация остаётся полной, просто неподвижной.

Правки без погружения в код:

- **Текст слайда и заметки** — в `index.html`. Ключевая часть заголовка в `<em>` подсвечивается и
  появляется «шторкой».
- **Время слайда** — атрибут `data-dur` (секунды) у `<section>`; по нему считаются таймер и автопоказ.
- **Темп анимации** — числа `at` (миллисекунды от входа на слайд) в сценах `motion.js`.

## Откуда материалы

- **Скриншоты веб-клиента** сняты с локального сервера на синтетическом сценарии `attention`
  (`npm run build`, затем `npm run demo:prepare -- --scenario attention --force` и `demo:start`), окно
  1280×720 при двойной плотности пикселей. Скриншоты оконного приложения взяты из `ui/docs/`.
- **Анатомия** — те же данные, что в приложении: `ui/tools/render_anatomy.py` из BodyParts3D, но при
  4 текселях на единицу вместо 2 (в скрипте `R = 4`, радиус затенения `pad = 48`, размытие `6.0`, ширина
  атласа `AW = 2048`). Полученный атлас и таблицу спрайтов раскрашивает `tools/export_anatomy.py` теми же
  формулами, что `ui/crates/ui-gui/src/figure.rs`:

  ```bash
  python presentation/tools/export_anatomy.py atlas.png sprites.rs presentation/assets/anatomy
  ```

  Нужны `numpy` и `opencv-python`.
