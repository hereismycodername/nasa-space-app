# Показ MARS: сценарий и чек-лист

Документ для всей команды: кто готовит демо-машину, кто ведёт показ, что говорить и что делать, если что-то пошло не так.
Все данные на показе синтетические. Это демонстрационный инструмент самонаблюдения, **не медицинское изделие**.

## 1. Подготовка демо-машины (за день / за 2 часа до показа)

**Ответственные:** Backend 2 (iwbhappy) + QA.

| # | Шаг | Как проверить |
|---|---|---|
| 1 | Установлены Node **24.x**, Rust (rustup), Git, MSVC Build Tools (Windows) или `build-essential` (Linux) | `node --version` → `v24.*`; `cargo --version` |
| 2 | Свежий код: `git clone` или `git pull` ветки `main` | `git log -1` — последний коммит из `main` |
| 3 | `npm ci` (нужен интернет один раз) | без ошибок |
| 4 | Полная автоматическая проверка | `npm run check`, `cargo test --locked`, `npm run test:smoke` — всё ok (на машине Backend 2 то же делает `full-check.cmd` → **7**) |
| 5 | Release-сборка | `npm run release` → в консоли `Ready: http://127.0.0.1:8080` и путь к admin |
| 6 | Сценарий показа | `npm run build`, затем `npm run demo:prepare -- --scenario attention --force`, затем `npm run demo:start -- --scenario attention` → UI открывается |
| 7 | **Второе устройство** (телефон/ноутбук в той же Wi-Fi) | запуск с `BIND_ADDR=0.0.0.0:8080`; узнать IP (`ipconfig` / `hostname -I`); открыть `http://<IP>:8080` на втором устройстве. Если не открывается — разрешить порт 8080 во входящих правилах брандмауэра Windows |
| 8 | **Без интернета** | отключить внешний интернет (оставить локальную сеть/Wi-Fi роутера), перезагрузить страницу — всё работает |
| 9 | **Остановка и перезапуск** | Ctrl+C в окне стенда → процесс завершился штатно («Server stopped gracefully»); запустить снова → данные на месте |
| 10 | Браузер | полный экран (F11), масштаб 100–110 %, закрыть лишние вкладки и уведомления |

Записать в чат команды: ОС, SHA `main`, что проверено и что нет.

## 2. Перед самым выходом (5 минут)

1. Пересоздать сценарий, чтобы данные были «до текущей минуты»: команды из шага 6 (на машине Backend 2 — `full-check.cmd` → **3**).
2. Открыть `http://127.0.0.1:8080`, вкладка **Обзор здоровья**, роль **CREW**.
3. Проверить: вверху «Связь установлена», в блоке оценки — «Требует внимания».
4. Держать открытым второе окно с готовым сценарием **stale** не нужно — переключение занимает ~20 с (см. шаг 6 показа).

## 3. Сценарий показа (3–5 минут)

| Время | Действие на экране | Что говорить |
|---|---|---|
| 0:00 | Обзор здоровья, 3D-фигура | «Астронавт на борту сам оценивает своё состояние. Данные идут с датчиков и из ручного ввода, всё хранится локально — связь с Землёй не нужна.» |
| 0:30 | Блок «Оценка показателей»: «Требует внимания», карточки **Сон** и **Самочувствие**; голова на фигуре подсвечена жёлтым | «Последние три дня сон 4–5 часов и самочувствие 2 из 5. Система объясняет, почему это важно в полёте, и что сделать: защищённое время для сна, разговор с экипажем, когда звать полётного врача. Каждое правило со ссылкой на источник.» |
| 1:15 | Раскрыть «Когда нужна срочная помощь» и «Что делать и почему» | «Это демонстрационные правила, не диагноз. Пороги и тексты сверены с открытыми источниками NASA и медицинских организаций.» |
| 1:45 | Вкладка **Динамика** → Пульс, 7 дней; затем Систолическое давление | «На графике видно: последние трое суток пульс покоя и давление выше обычного. Пропуски в данных не дорисовываются.» |
| 2:15 | Клик по голове на фигуре → **Внести измерение** → Головная боль = 5 → сохранить | «Симптом — одним кликом по схеме тела. Значение сразу попадает в историю и в общую картину.» |
| 2:45 | Блок задач: отметить «Заполнить ежедневные измерения» | «Ежедневные задачи привязаны к дате миссии.» |
| 3:00 | Переключить роль **GROUND** | «Тот же сервер — вид для полётного врача на Земле: все каналы на одной шкале времени, статусы, свежесть данных.» |
| 3:30 | Системы организма: 12 показателей, у старых замеров «Последний замер N ч назад» | «Система честно показывает, когда измерение не свежее, и не выдаёт старые данные за текущие.» |
| 3:50 | (опционально) телефон: тот же UI по Wi-Fi | «Работает в локальной сети корабля с любого устройства.» |
| 4:10 | Итог | «Наблюдение, объяснение, действие, эскалация — без интернета. Следующий шаг — реальные датчики через готовый шлюз и проверка на бортовом компьютере.» |

**Не обещать:** диагнозы, медицинскую точность, работу на Raspberry Pi и с физическими датчиками (не проверено).

## 4. Если что-то пошло не так

| Проблема | Что сделать |
|---|---|
| «Нет связи» / страница не грузится | окно стенда закрыто или упало → запустить шаг 6 заново (~20 с) |
| «Порт 8080 уже занят» | закрыть старое окно стенда (или в Диспетчере задач завершить `space-health-server`) и запустить снова |
| Данные выглядят старыми | пересоздать сценарий (`demo:prepare -- --scenario attention --force`) |
| Второе устройство не открывает | проверить, что запуск с `BIND_ADDR=0.0.0.0:8080`, оба устройства в одной сети, порт 8080 разрешён в брандмауэре |
| 3D-фигура не отображается | переключить **2D** над фигурой (та же логика, без WebGL) |
| Всё сломалось за минуту до выхода | показывать на ноутбуке backend-2 со скриншотами из `docs/` и этим сценарием как опорой |

## 5. Материалы для сдачи (продуктовый участник)

- Описание проекта: задача, решение, для кого, что реально работает (по этому документу).
- Ссылка на репозиторий (`main`).
- Короткое видео или слайды: записать прогон раздела 3 (2–3 минуты).
- Источники знаний: NASA Human Research Program и источники, указанные в правилах BE-08.
- Честные ограничения: синтетические данные, демонстрационные пороги, железо не проверено.
