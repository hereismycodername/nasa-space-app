# Как AstroCheck использует материалы NASA

## Что действительно используется

В приложение встроен курируемый каталог `space-health-research-2026-11-15-v2`:
[resources/nasa/catalog.json](../resources/nasa/catalog.json).
Он содержит десять записей: шесть рисков NASA, два исследования NASA и два материала CSA, краткие русские
пересказы, название исходного раздела, URL, дату проверки и связи с показателями.
Это структурированная справочная информация, не набор экспериментальных измерений.

Источники NASA проверены 15 ноября 2026 года:

- NASA HRP, [Risks of Human Spaceflight](https://www.nasa.gov/hrp/risks/).
- NASA HRP, [Ongoing HRP Research in Space](https://www.nasa.gov/hrp/ongoing-hrp-research/).

Пользователь предоставил эти источники в контексте ресурсов задания. Соответствие
актуальному списку Resources и допустимость справочных материалов вместо числового
датасета следует подтвердить у организаторов. Мы не заявляем, что каталог сам по
себе гарантирует допуск на глобальный этап.

## Как информация влияет на приложение

Единый JSON импортируется React и встраивается в Rust ui-model при сборке.
Он используется во всех трёх интерфейсах, а не просто лежит в репозитории.
`catalog.ts` выбирает записи по ID показателя. `NasaMetricContext` показывает
результат в карточках измерений и в разделе динамики. При выборе системы на
3D-карте фильтруются показатели, вместе с ними — связанные материалы.
Вкладка «Источники NASA» позволяет независимо фильтровать весь каталог.

Каждая запись разделяет:

1. Краткое содержание материала NASA.
2. «Как используем» — решение команды о назначении функции.
3. Ограничение интерпретации.
4. Ссылку на источник с точным названием раздела.

Пример: материал о сердечно-сосудистой адаптации связан командой с пульсом и
двумя компонентами давления. Это обосновывает наблюдение и контекст, но не
диагностирует адаптацию. Для glucose и headache прямые связи в этой версии
не назначены; интерфейс честно сообщает об этом.

Каталог работает без внешних запросов после загрузки приложения. Это не означает,
что само приложение можно впервые открыть без локального сервера. Для чтения
оригинальных страниц NASA нужен интернет. Обновление каталога ручное: проверить
страницы, исправить пересказы/связи, обновить reviewedAt/version и запустить тесты.

## Что НЕ является данными NASA

- Питч-показания генерирует наш симулятор; они синтетические.
- Связи риска с нашими метриками и шкалами — интерпретация команды.
- Числовые пороги BE-08 имеют отдельные основания AHA/NHS/CDC или явно указаны
  как решения команды. Каталог NASA не меняет оценку и пороги.
- 3D-модель BodyParts3D имеет собственное происхождение и не выдаётся за ресурс NASA.
- Мы не воспроизводим исследовательские протоколы и не заявляем одобрения NASA.

## Демонстрация для жюри (около минуты)

1. Открыть AstroCheck с работающим `npm run pitch`.
2. Выбрать сердце на карте или его подпись. Показать реальные ответы нашего API.
3. Раскрыть «NASA: зачем отслеживать показатель» у пульса. Показать содержание,
   наше применение, ограничение и оригинальную ссылку.
4. Открыть «Источники NASA» и выбрать «Сон»: состав материалов меняется по
   сохранённым связям. Показать ARCHeR и дату проверки каталога.
5. Пояснить, что данные датчиков синтетические, а NASA предоставляет научный
   контекст выбора наблюдений. Это два разных слоя проекта.

Текст для выступления:

> Мы превратили материалы NASA Human Research Program в локальный каталог,
> связанный с показателями. При выборе показателя приложение объясняет, зачем
> мы наблюдаем его в космическом полёте, показывает ограничения и первоисточник.
> Связи с функциями разработала наша команда. На демонстрации данные датчиков
> синтетические; мы не выдаём их за измерения NASA или доказательство диагноза.

Проверки: `npm run check`. Тесты каталога проверяют происхождение ссылок,
валидность связей, выбор материалов и явное отсутствие неподтверждённых связей.

## Оконная и терминальная версии

- Оконная версия с общим API: вкладка **NASA** показывает полный каталог.
  В карточке показателя раскройте **NASA: research context / научный контекст**:
  там только связанные материалы и кликабельные первоисточники.
- Терминальная версия с общим API: выберите показатель стрелками и нажмите **n**.
  **Shift+N** открывает весь каталог. Стрелки и PageUp/PageDown прокручивают,
  Esc закрывает окно. URL источников напечатаны полностью.
- Справочные тексты каталога русские, в том числе при выборе EN в оконном клиенте.
- Обе Rust-сборки содержат каталог внутри бинарника; отдельный JSON рядом с exe
  и интернет для чтения справки не нужны. Для обновления требуется пересборка.

Проверка нативных клиентов: `cargo test --manifest-path ui/Cargo.toml`.

## Практическое применение через общий сервер

`GET /api/assessments` дополнен необязательным для старых клиентов полем
`researchInsights`: сон, пульс, систолическое и диастолическое давление, активность.
Сервер соединяет общий каталог с тем же снимком измерений и качеством данных,
который используется для оценки BE-08. Ответ содержит ID записи, время, значение,
источник измерения, научный контекст, применение командой, ограничения и ссылки.
Пример одной записи: [research-insight.json](examples/research-insight.json).

В браузере и окне откройте показатель → «Что это значит в полёте».
Кнопки открывают ввод измерения, историю и существующую оценку BE-08.
В терминале выберите показатель → `n`, затем `1` (ввод), `2` (история в основной
панели) или `3` (оценка BE-08). Ввод отправляется только после подтверждения
пользователем; открытие пояснения не создаёт измерение и не завершает задачу.
После сохранения измерения клиенты получают новое пояснение при опросе API.

Пояснения описывают снимок на указанное время, а не постоянно актуальный статус.
Нет данных / устаревшие / неизвестное время / часы в будущем различаются явно.
Оценка BE-08 сохраняет собственные проверки актуальности и ограничения.
Активность пока не имеет автоматического клинического правила: кнопка оценки
показывает это ограничение, не выдумывая норму нагрузки NASA.

В этой версии автоматического сравнения с личной нормой и анализа тренда нет:
для этого есть действие просмотра истории. Систолическое и диастолическое
давление представлены отдельно; сервер не объявляет разные замеры одной парой.
Нужно перезапустить обновлённый сервер и нативные клиенты, обновить страницу.
Старый сервер без researchInsights оставляет статический каталог доступным.

## Дополнительные источники CSA

Проверены 15 ноября 2026 года:

- [Monitoring radiation for astronaut health](https://www.asc-csa.gc.ca/eng/news/articles/2026/2026-02-26-monitoring-radiation-astronaut-health.asp), 26 февраля 2026.
  Запись о CANS доступна в полном каталоге всех клиентов. Объясняет необходимость
  отдельного радиационного измерителя и отсутствие такого канала у AstroCheck.
  Не связывается с пульсом, температурой или другими косвенными признаками.
- [Why do we conduct science experiments in space?](https://www.asc-csa.gc.ca/eng/iss/science/why-do-we-conduct-science-experiments-in-space.asp), обновлено 28 октября 2025.
  Раздел о применении результатов исследований обосновывает контекст активности,
  сердца и сосудов. Сервер добавляет его в пояснения пульса, давления и активности.
  Связи — интерпретация команды, без числовых норм и причинных диагнозов.

Каждый источник имеет agency; API передаёт sourceAgency. Интерфейсы подписывают
источники NASA или CSA отдельно. Канадские материалы дополняют использование NASA,
не заменяя его для требования конкурса. В каталог включены краткие пересказы,
а не данные экспериментов или телеметрия CANS.
