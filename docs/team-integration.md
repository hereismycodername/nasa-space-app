# Интеграция веток команды после BE-06

Базовый HTTP-контракт — [BE-06 / v0.6.0](contracts.md). Он сохранён вместе с
исходными миграциями 0001–0003; новую альтернативную миграцию 0003 не применяем.

## Что перенесено

Из веток iwbhappy `feature/be-04-latest-history` и `feature/be-05-series`
(7992cbc, 2b8bd40, d604fa5) перенесены идеи единого реестра метрик/единиц/агрегации
и одной SQL-выборки latest. Реализация адаптирована к нашему контракту:
сохранены три представления latest, оба quality, cursor истории и все поля series.
Среднее остаётся устойчивым к переполнению; UTC-диапазон проверяется после
нормализации. Эти случаи покрыты регрессионными тестами.

Ветка Asterisksy-zxc `ui` объединена до bbcba59 включительно. Её шрифты,
BodyParts3D и принципы Ground-консоли перенесены в React: дерево показателей,
общий диапазон нескольких графиков, текущие наблюдения, выбранный профиль.
Геометрия и anchors экспортируются вместе; соответствие generated-файла проверяет CI.

Следующие визуальные изменения `ui` (`6d9e3e1`, `b24fa01`) адаптированы в React
отдельно от native-кода: приборная палитра, прямые углы и срезы панелей,
сегментные шкалы, квадратные маркеры и затемнение остальных систем при выборе.
В этот дизайн встроена локальная объёмная модель BodyParts3D: поворот, масштаб,
выбор органов и резервная 2D-карта. Выбранная система остаётся видна при смене слоя.
Геометрия и происхождение описаны в [public/anatomy](../public/anatomy/README.md).

Новый `ui-backend` из `6d9e3e1` содержит отдельное native-хранилище, собственную
миграцию `0003_ui.sql` и демонстрационные оценки. Этот backend не подключён
к основному приложению: React продолжает обращаться к серверу BE-06. Дизайн
шкал перенесён с семантикой полноты данных, без добавления клинических порогов,
фиктивных профилей, ACK или uplink.

React использует единственный действующий профиль и реальные API-записи.
Демонстрационные медицинские нормы, дополнительные члены экипажа, ACK и uplink
из native-демо требуют будущих backend-возможностей. Текущие наблюдения — сводка
quality из latest, а не постоянный журнал событий.

## Исправления native-демо

- Подписи TUI относятся к показанным 40 измерениям, а не началу полной истории.
- PageUp/PageDown позволяет увидеть все выбранные каналы.
- Все графики GUI Ground используют общий диапазон и при выборе All.
- Native workspace получает отдельный CI job; root Cargo workspace содержит сервер.

## Три интерфейса с общими данными

GUI и TUI по умолчанию используют новый адаптер `ui-http`, который обращается
к тому же серверу BE-06, что и React. Отдельное native-хранилище не создаётся.
Общими остаются профиль `demo-astronaut`, шесть показателей, семидневная история
и выполнение задач. Запуск из корня репозитория после запуска сервера:

```bash
cargo run --locked --manifest-path ui/Cargo.toml -p ui-gui
cargo run --locked --manifest-path ui/Cargo.toml -p ui-tui
```

Адрес задаётся через `--api-url` или `ASTROCHECK_API_URL`; по умолчанию
`http://127.0.0.1:8080`. Старый автономный прототип доступен только с `--demo`.
3D с вращением остаётся в React; оконная версия сохраняет 2D-анатомию,
терминальная показывает таблицы и графики.

HTTP работает в фоновом потоке. Измерения и задачи обновляются примерно каждые
2 секунды, графики — каждые 10 секунд. Видны источник, время измерения/получения,
все пять состояний quality BE-06 и пропуски на UTC-шкале. При отключении сервера
показываются ошибка и ранее загруженные данные. Клинические оценки не вычисляются.

Ручной ввод отправляется от `manual-01`, с отдельной сессией клиента и последовательностью.
Успех показывается только после подтверждения API. Повторы измерения сохраняют
исходный payload и ключ дедупликации. При потере ответа PATCH задачи автоматически
не повторяется: старый контракт изменяет время выполнения; результат уточняется
последующим чтением. Незавершённая отправка хранится в памяти, поэтому перед
закрытием клиента нужно дождаться подтверждения.

Проверены 41 тест native workspace, сборка обоих бинарников и Clippy нового
HTTP-адаптера. `npm run test:native-api` проверяет настоящий Rust API с временной
SQLite, двумя независимыми native-адаптерами и запросами браузерного контракта:
запись и чтение дробных значений, общие задачи, provenance, quality, историю
и дедупликацию. Проверка добавлена в CI.

На macOS проверен ввод через настоящее окно GUI: значение появилось в React.
Собранный TUI в PTY прочитал это значение, сохранил новое измерение и отметил
задачу с подтверждением сервера. Проверки выполнялись на отдельной тестовой БД.
Текущие HTTP-бинарники на Windows и физической Raspberry Pi пока не проверены.

## Запуск и датчики

`npm run doctor` проверяет окружение, `npm run demo` собирает приложение и запускает
сервер с симулятором, ожидая готовность API. Команда прекращает свои дочерние процессы
при остановке; занятый порт диагностируется без завершения чужого процесса.

Локальный `space-health-admin` регистрирует устройства в существующей таблице,
не добавляя публичных административных endpoints. Python-шлюз передаёт NDJSON
из stdin или USB/UART с постоянной очередью одного неподтверждённого сообщения;
повторы и перезапуски сохраняют исходный payload и ключ дедупликации.

Сервер и мост проверяются локально, включая источник `sensor`. Это не аппаратный
тест: модель Pi, ОС и журналы ошибок тестировщика не предоставлены. Целевая
конфигурация, systemd, протокол платы и ограничения изложены в [hardware.md](hardware.md).

## Интеграция демосценариев BE-09

Ветка `feature/be-09-demo-data` перенесена до `e224f94` включительно.
`demo:prepare` и `demo:start` добавляют воспроизводимую семидневную историю
для `baseline`, `attention`, `stale` и `delayed`. Все шесть показателей, включая
парные систолическое и диастолическое давления, сохраняются через API BE-06
в отдельные `demo/<scenario>.db`. Контракт и подключение трёх интерфейсов сохранены.
Сценарий `attention` меняет синтетические значения; клинических правил BE-08
эта интеграция не добавляет.

При переносе исправлена проверка запуска: занятый порт отклоняется, а ответ
health принимается только после сообщения собственного дочернего сервера
об успешном bind. Это исключает запуск симулятора против уже работающего демо
из-за чужого ответа health. Проверки охватывают занятый порт, появление слушателя
после предварительной проверки и штатный запуск/остановку собственного сервера.

При интеграции прошли lint, production build, 89 тестов Vitest, 106 тестов
сервера, rustfmt/Clippy, 9 Node-тестов и 7 Python-тестов. Успешны API smoke,
обычный demo smoke и проверка общих данных native/API.

Прогон всех сценариев через настоящий API с seed=42 и
reference=`2026-11-14T21:18:00.000Z` создал 2079 записей baseline, 2079 attention,
2001 stale и 2078 delayed. Latest содержит все шесть показателей; суммы отсчётов
семидневных series совпали с генератором, пары давлений имеют одинаковое время.
Повтор всех 2081 пакета delayed вернул только HTTP 200, не изменив сохранённые
ID и временные метки. `stale` при запуске не добавляет записи; три новых live-пакета
`attention` продолжили его профиль. Оба запуска завершились штатно по SIGINT
и освободили порты. Этот прогон выполнен на macOS; Windows и Raspberry Pi
в рамках интеграции не проверялись.

## BE-08: общая оценка в трёх интерфейсах

`GET /api/assessments` совместимо дополнен `health`: шесть версионированных
демонстрационных правил, причины, следующие действия, обращения за помощью,
ссылки на источники и объяснения пяти опасностей полёта. Качество BE-06 и
legacy-поля сохранены. Правила используют только пригодные измерения и возвращают
их ID и срок действия. Подробности: [be08-rules.md](be08-rules.md).

React, GUI и TUI читают одну серверную оценку. Клиенты снимают текущий статус
при истечении срока, потере связи и смене измерения; числовых порогов в клиентах
нет. React сохраняет предыдущие предупреждения с явной отметкой времени.
Оконная карта остаётся двумерной, 3D — только в браузере.

Серверную часть B/C реализовал iwbhappy в `feature/be-metrics-bc`; согласование —
[Issue #6](https://github.com/hereismycodername/nasa-space-app/issues/6#issuecomment-6884532125).
Коммиты `9669dac`, `9267763`, `04d39b0` интегрированы поверх BE-08.
Клиенты поддерживают двенадцать показателей, но открывают ввод и запрашивают историю только для объявленных
сервером метрик. Для новых показателей без правил предусмотрен `notEvaluated`,
а не зелёная оценка. Сохранена совместимость со старым сервером на шесть метрик.

Проверены 125 тестов React, 132 теста Rust-сервера, 50 тестов native workspace,
9 Node-тестов и 7 Python-тестов шлюза,
frontend lint/build, серверные rustfmt/Clippy, OpenAPI и генерация анатомии.
Строгий Clippy HTTP-клиента запускался с `--no-deps`; общий native rustfmt и
проверка зависимостей Clippy всё ещё замечают старый стиль и предупреждения
в коде автономного демо. Массовое переформатирование этого кода не входит в BE-08.
OpenAPI имеет прежнее предупреждение об отсутствии license; Vite — о размере
отдельного динамически загружаемого 3D-модуля.

`npm run test:assessment` проверяет реальный API на отдельной БД: отсутствие
данных, устаревшее/неизвестное/будущее время, переходы noAlert → attention →
critical, ID доказательств, действия и повтор без дублей. Прошли также основной
API smoke, demo smoke и native/API acceptance с двумя независимыми клиентами.

Дополнительно после B/C через отдельные временные БД прогнаны все четыре
сценария (seed=42, reference=`2026-11-14T21:00:00.000Z`): baseline и attention
создали по 2289 строк, stale — 2204, delayed — 2289 и три подтверждённых повтора.
Latest содержит 12 метрик; суммы отсчётов всех 12 series совпали с генератором.
Повтор 2292 пакетов delayed вернул HTTP 200 с исходными ID и timestamps.
Реальные ответы сервера также прошли runtime-парсер React: нули/дроби B/C
сохранились в latest/history/series, повтор дал прежний ID, glucose=0 отклонён.
Новые метрики остались `notEvaluated` при любых пригодных значениях.

На macOS визуально проверены срочный сигнал в GUI и браузере, TUI в PTY,
запись через React с обновлением оценки, выбор головы → запись headache=0.5,
Crew/Ground, ширина 390 px без
горизонтального переполнения и offline с сохранённым прошлым предупреждением.
Тестовый сервер остановлен; рабочая БД демо не менялась. Windows, физические
платы и медицинская пригодность правил этим прогоном не подтверждаются.

## Обновление UI aec7101 и совместимость с питчем

Ветка `ui` объединена до `aec7101` с сохранением локального питч-симулятора.
Обновление включает React demo-polish, затенённую 2D-анатомию и оформление
native GUI/TUI, а также уже согласованные BE-07 и BE-11. Браузер сохраняет
вращаемую 3D-модель; все три интерфейса используют общий Rust API.

BE-07 меняет контракт задач: `GET /api/tasks` возвращает `{missionDate, tasks}`,
а обновление явно передаёт дату миссии. Сервер и все три клиента необходимо
обновлять вместе. Поддержка реестра из шести метрик не означает поддержку старого
массива задач BE-06. Повторная отметка задачи сохраняет первоначальное время
выполнения; клиенты по-прежнему уточняют состояние чтением после потери ответа.

Приняты окна свежести demo-polish: пульс 15 секунд, SpO₂ 2 часа,
давления/температура/боль 13 часов, ежедневные показатели 26 часов.
Это политика качества данных, не медицинские пороги. Клиенты используют сроки
из API; числовые правила BE-08 остаются на сервере. В сцене `stale` питча пульс
по-прежнему естественно теряет свежесть после 15 секунд.

При адаптации исправлена подпись устаревшего пульса: вместо «только что»
показываются ожидание нового замера и возраст в секундах. Добавлено объяснение
региональной подсветки скелета. Питч отключает подробный HTTP-журнал по умолчанию
(`REQUEST_LOG=1` включает его), сохраняет временную БД и управление сценами.
OpenAPI и примеры согласованы с новыми окнами; прежние fixtures явно обозначены.

Проверки интеграции: 129 тестов React, 135 тестов Rust-сервера, 54 native-теста,
23 Node-теста инструментов, frontend lint/build и серверные rustfmt/Clippy.
Пройдены native/API acceptance с двумя клиентами и BE-08 acceptance на временных
БД; все 24 JSON-примера ответов проверены по OpenAPI. На macOS проверены живой
питч, вращение/подсветка модели, консоль Земли и общие задачи, узкая компоновка,
а также новое окно GUI на том же API. Прежнее предупреждение о размере
динамического 3D-модуля остаётся. Windows и физические платы здесь не проверялись.
